# scr.sh + /scripts — набор серверных скриптов

Коллекция bash-утилит для рутинных задач администрирования Linux-серверов с единой
точкой входа: загрузчик `scr.sh` показывает меню, подтягивает нужный скрипт с вашего
веб-сервера, выполняет его и удаляет за собой.

**Версия:** 1.0
**Автор:** Urdin-at <urdin@yandex.ru>

---

## Как это работает

```
пользователь                          ваш веб-сервер
    │                                        │
    ├── GET /scr.sh ────────────────────────►│   загрузчик (меню)
    ├── GET <SERVER_URL>/index.txt ────────►│   список «файл - описание»
    ├── GET <SERVER_URL>/<выбранный скрипт> ►│   сам скрипт → во временный файл
    └── bash <временный файл> ──────────────► выполнение → файл удаляется
```

На серверах-клиентах ничего хранить не нужно (только `curl` и `bash`), версии не
расходятся: все получают то, что лежит на сервере сейчас.

## Установка на ваш сервер

1. Распаковать архив в каталог, который раздаётся веб-сервером:
   ```bash
   tar -xzf urdin-scripts-1.0.tar.gz -C /путь/к/сайту/
   ```
   Получится:
   ```
   <корень сайта>/
   ├── scr.sh              # загрузчик
   └── scripts/
       ├── index.txt       # список: «имя_файла - описание»
       └── *.sh            # сами утилиты
   ```

2. Прописать адрес сервера в `scr.sh` — вместо заглушки:
   ```bash
   SERVER_URL="https://example.com/scripts"   # ← заменить на свой адрес
   ```
   Адрес указывает на каталог, в котором лежат `index.txt` и скрипты. Заглушка
   `https://example.com/scripts` оставлена специально: пока её не заменить, загрузчик
   работать не будет — и это заметно сразу, а не «через месяц непонятных сбоев».

3. Проверить, что загрузчик доступен по адресу `https://ваш-домен/scr.sh`.

---

## Использование

```bash
curl -fsSL https://ваш-домен/scr.sh -o scr.sh && bash scr.sh
```

Дальше — номер пункта в меню; после выполнения скрипта вы возвращаетесь в меню
(пункт `0` — выход с очисткой экрана).

Права root нужны только тем утилитам, которые меняют систему (пакеты, логи, fail2ban,
SSH-настройки, cron). Информационные (`sysinfo.sh`, `monitoring.sh`) работают от любого
пользователя.

## Утилиты

### sysinfo.sh — сводная информация о системе
Показывает: количество ядер CPU, объём ОЗУ, подключённые диски, дистрибутив и его версию,
тип пакетов (DEB/RPM).
**Настройки:** не требуются — только чтение, система не изменяется.
**Требования:** `bash`, `nproc`, `lsblk`, `awk`; `dpkg` или `rpm` по наличию.

### aliases.sh — алиасы оболочки
Пункты меню: показать алиасы; добавить; удалить; поставить готовый набор; включить
применение алиасов для root.
**Настройки:** состав готового набора — в функции `add_default_aliases` (массив
`default_aliases`). По умолчанию: `ll`, `cls`, `grep`, `hg`, `net`, `cat` + `update`/`install`
под обнаруженный пакетный менеджер. Алиасы пишутся в `~/.bashrc`; для root — в `/root/.bashrc`
и `~/.profile`.
**Требования:** `bash`; root — только для пункта про root.

### sshkeys.sh — авторизация по SSH-ключам
Пункты меню: проверить вход по ключу (текущий пользователь и root); включить авторизацию
по ключу (правит `sshd_config`, создаёт `~/.ssh`, генерирует ключ при необходимости);
вывести список ключей; добавить новый ключ (с проверкой дубликатов).
**Настройки:**
- **вшитый ключ** (пункт меню 6) — переменная `embedded_key` в функции `add_embedded_key()`:
  впишите свой публичный SSH-ключ одной строкой (содержимое `~/.ssh/id_ed25519.pub`).
  По умолчанию там **заглушка** `REPLACE_WITH_YOUR_PUBLIC_KEY` — пока её не заменить,
  скрипт откажется добавлять ключ и подскажет, где правка (никакого мусора в
  `authorized_keys` не появится);
- пути стандартные и настройки не требуют: `~/.ssh/authorized_keys` для пользователя,
  `/root/.ssh/authorized_keys` для root.
**Требования:** `bash`; root — для правки настроек sshd и ключей root.

### soft.sh — установка базового набора программ
Определяет пакетный менеджер (`apt`/`yum`/`dnf`), обновляет список пакетов и ставит
программы из списка.
**Настройки:** `PROGRAMS=(...)` — список устанавливаемых программ. По умолчанию:
`curl`, `mc`, `ncdu`, `htop`, `bat`, `ripgrep`, `btop`.
**Требования:** `bash`, права root, доступ к репозиториям.

### mysql_backup.sh — мастер резервного копирования MySQL
Проверяет, требует ли root MySQL пароль; показывает базы и даёт выбрать нужные; спрашивает
каталог хранения, расписание (ежедневно / еженедельно / ежемесячно / свой cron-формат) и
количество хранимых копий; создаёт скрипт бэкапа с логированием и ставит задание в cron.
**Настройки:** `LOG_FILE` — журнал (по умолчанию `/var/log/mysql_backup.log`); остальные
параметры задаются в диалоге.
**Требования:** `bash`, `mysql`/`mysqldump`, права на каталог копий и `crontab`.

### log_manager.sh — работа с логами
Пункты меню: очистить старые логи; настроить ротацию; список логов с размерами; просмотреть
лог.
**Настройки** (в начале файла):
- `LOG_DIR` — каталог логов (по умолчанию `/var/log`);
- `MAX_SIZE` — порог размера для ротации (например, `50M`);
- `ROTATE_COUNT` — сколько ротаций хранить;
- `EXCLUDE_FILES` — маски исключений (`*.gz *.bz2 *.xz`).
**Требования:** `bash`, права root (запись в каталог логов).

### monitoring.sh — мониторинг состояния системы
Пункты меню: CPU (`top -bn1`), память (`free -h`), диск (`df -h`), сетевые адреса (`ip addr`),
топ процессов по CPU (`ps aux`).
**Настройки:** не требуются — только чтение.
**Требования:** `bash`, `top`, `free`, `df`, `ip`, `ps`.

### f2b.sh — управление fail2ban
Проверяет наличие и состояние fail2ban; при отсутствии — устанавливает подходящим пакетным
менеджером; скачивает конфиги jail/filter/action с вашего веб-сервера и раскладывает по
`/etc/fail2ban/`; перезапускает сервис; показывает статистику по jail'ам.
**Настройки** (в начале файла):
- `WEB_SERVER` — адрес сервера с конфигами. **Стоит заглушка `https://example.com`** —
  замените на свой домен;
- `JAIL_PATH` — путь к каталогу jail-конфигов на сервере (`/scripts/fail2ban/jail`);
- `FILTER_PATH` — путь к каталогу filter-конфигов (`/scripts/fail2ban/filter`).
**Требования:** `bash`, `curl`, права root; сам fail2ban устанавливается по выбору.

### nano.sh — настройка nano
Пункты меню: показать текущий `~/.nanorc`; применить рекомендованный набор настроек;
очистить `~/.nanorc` (с автоматическим бэкапом `.bak.ГГГГММДД-ЧЧММСС`).
**Настройки:** `NANORC` — путь к конфигу (по умолчанию `~/.nanorc`); состав набора —
в функции `apply_settings` (массив `SETTINGS`).
**Требования:** `bash`, `nano`.

## Добавить свою утилиту

1. Положить файл в `scripts/` (shebang `#!/bin/bash`, единый UI-блок — см. ниже).
2. Добавить строку в `scripts/index.txt`:
   ```
   my_script.sh - Краткое описание для меню
   ```
3. Готово: пункт появится у всех, кто запускает загрузчик. Клиенты обновлять не нужно.

**Шаблон шапки** (для единообразия):

```bash
#!/bin/bash
# =============================================================================
# my_script.sh — краткое назначение.
#
# Что делает:
#   - ...
#
# Настройки: ... (или «не требуются»)
#
# Требования: ...
#
# Автор: Имя <mail@example.com>
# Версия: 1.0
# =============================================================================
```

**UI-блок** (копируется в каждый скрипт без изменений):

```bash
RED=$'\033[0;31m'; GREEN=$'\033[0;32m'; YELLOW=$'\033[1;33m'
BLUE=$'\033[0;34m'; CYAN=$'\033[0;36m'; BOLD=$'\033[1m'; NC=$'\033[0m'

ui_title() { clear 2>/dev/null || true; printf '%s\n' "${CYAN}═══...═══${NC}"; printf '%s\n' "${BOLD}${YELLOW}  $*${NC}"; printf '%s\n' "${CYAN}═══...═══${NC}"; }
ui_item()  { printf ' %s\n' "${GREEN}$1)${NC} $2"; }
ui_ask()   { printf '%s' "${GREEN}Выберите пункт [0-$1]: ${NC}"; }
ui_pause() { printf '\n%s' "${YELLOW}Нажмите Enter для продолжения...${NC}"; read -r _ || true; }
ui_ok()    { printf '%s\n' "${GREEN}$*${NC}"; }
ui_err()   { printf '%s\n' "${RED}$*${NC}"; }
ui_warn()  { printf '%s\n' "${YELLOW}$*${NC}"; }
ui_info()  { printf '%s\n' "${CYAN}$*${NC}"; }
```

## Требования

- Linux с `bash` (Debian/Ubuntu, RHEL/CentOS/Alma/Rocky и производные);
- `curl` — загрузчик предложит установить его, если не найден;
- для части утилит: права root и профильные пакеты (`mysql`, `fail2ban`, `nano`).

---

## Стиль кода

- shebang `#!/bin/bash`, UTF-8, переводы строк LF;
- общий UI-блок и единый вид меню (рамка-заголовок, `N) текст`, `0) Выход`,
  приглашение `Выберите пункт [0-N]: `);
- пауза после действий с выводом — чтобы успеть прочитать, и **нет** паузы
  при выходе и неверном вводе;
- переменные в кавычках, `read` всегда с `-r`;
- проверки перед коммитом: `bash -n <файл>` и `shellcheck <файл>` — без замечаний.

---

## Безопасность

- скрипты запускаются от имени того, кто запустил загрузчик — читайте, что выполняете;
- каждый скрипт выводится через меню: ничего не выполняется скрыто;
- скачанный файл пишется во временный каталог и удаляется после выполнения;
- в проекте нет паролей, приватных ключей и адресов конкретных серверов — адреса
  оформлены заглушками, которые вы заменяете на свои.
